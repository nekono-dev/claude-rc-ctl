# claude-rc-ctl 要件定義書

## 1. 目的

Linux サーバ上で、複数のディレクトリそれぞれに対して Claude Code の remote-control を常駐サービスとして動かし、その登録・起動・停止・状態確認・画面接続を単一のコマンドで管理できるようにする。あわせて、コマンド自体を一般ユーザー権限のワンライナーで導入・更新・削除できるようにする。

## 2. スコープ

### 2.1 対象

- 常駐インスタンス（ディレクトリ単位）の登録・解除・起動・停止・再起動・状態確認。
- インスタンスの tmux 接続とログ表示。
- コマンド本体の導入・更新・削除・導入情報の表示。

### 2.2 対象外

- Claude Code 本体の導入。
- root 権限が必要なシステム全体への導入。
- Linux 以外の OS への対応。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: ディレクトリを登録すると、そのディレクトリを作業先とする常駐サービスが、オプションで指定した起動方式（same-dir または worktree、既定は same-dir）で起動する。
- FR-2: 登録解除を指示すると、サービスを停止して登録情報を削除する。
- FR-3: 登録済みインスタンスの名前・状態・作業ディレクトリを一覧表示する。
- FR-4: 登録済みインスタンスを名前で指定して、起動・停止・再起動・状態表示ができる。
- FR-5: 登録済みインスタンスの tmux 画面へ接続でき、直近の画面出力とジャーナルを表示できる。
- FR-6: 常駐サービスは tmux 内で remote-control を起動し、起動方式・権限モード・effort（既定は medium）を登録情報から決める。
- FR-7: 不正な名前・存在しないディレクトリ・重複した名前での登録を拒否する。
- FR-8: 登録時に、起動方式が worktree で git リポジトリでないディレクトリと、未信頼のディレクトリへ警告を表示する。
- FR-9: インストーラは一般ユーザー権限で本体を導入し、再実行しても同じ結果になる。
- FR-10: 導入後のコマンドから、導入時に指定したブランチまたはタグの最新へ更新できる。
- FR-11: 導入後のコマンドから本体を削除でき、パージ指定時だけ登録情報と設定も削除する。
- FR-12: 導入後のコマンドから、導入先・取得元・コミット・更新日時を表示できる。

## 5. 非機能要件

- NFR-1: 常駐サービスが異常終了した場合、10秒以内に自動で再起動を開始する。
- NFR-2: 登録済みインスタンスが10件のとき、一覧表示を3秒以内に終える。
- NFR-3: 導入・更新・削除のいずれでも、管理者権限への昇格を0回しか要求しない。

## 6. 受け入れ条件

- AC-1 (FR-1): ディレクトリを登録すると、登録情報に作業ディレクトリが保存され、サービスが有効化と同時に起動される。
- AC-2 (FR-1): 名前を省略して登録すると、ディレクトリ名が登録名になる。
- AC-3 (FR-2): 登録解除すると、サービスが無効化と同時に停止され、登録情報が削除される。
- AC-4 (FR-3): 一覧に登録済みのすべてのインスタンスについて名前・状態・作業ディレクトリが1行ずつ表示される。
- AC-5 (FR-4): 起動・停止・再起動・状態表示の各指示が、対象インスタンスのサービスへ渡される。
- AC-6 (FR-5): 接続を指示すると、対象インスタンス専用の tmux ソケットへ接続する。
- AC-7 (FR-5): ログ表示を指示すると、画面出力とジャーナルの両方が表示される。
- AC-8 (FR-6): 登録情報に値がないとき、起動方式は same-dir、権限モードは auto で remote-control が起動される。
- AC-9 (FR-6): 登録情報に起動方式と権限モードがあるとき、その値で remote-control が起動される。
- AC-10 (FR-6): サービス定義は tmux のインスタンス専用ソケット内でセッションを作成して起動する。
- AC-11 (FR-7): 不正な名前・存在しないディレクトリ・登録済みの名前のいずれでも、登録情報を作らずに失敗する。
- AC-12 (FR-8): 起動方式が worktree で git リポジトリでないディレクトリと、未信頼のディレクトリを登録すると、それぞれ警告が表示され、same-dir では git リポジトリでなくても警告されない。
- AC-13 (FR-9): インストーラを実行すると、コマンドとサービス定義が配置され、2回実行しても結果が変わらない。
- AC-14 (FR-9): 管理者として実行すると、何も変更せずに失敗する。
- AC-15 (FR-10): 取得元に新しいコミットがあるとき、更新を指示すると導入先がそのコミットになる。
- AC-16 (FR-11): 削除を指示すると、本体とサービス定義が消え、登録情報は残る。
- AC-17 (FR-11): パージ付きで削除を指示すると、登録情報と設定も消える。
- AC-18 (FR-12): 導入情報の表示を指示すると、導入先・取得元・コミット・更新日時が表示される。
- AC-19 (NFR-1): サービス定義は常に再起動する設定で、再起動までの待ち時間が10秒である。
- AC-20 (NFR-2): 登録済みインスタンスが10件のとき、一覧表示が3秒以内に終わる。
- AC-21 (NFR-3): 昇格コマンドが失敗する環境で、導入・更新・削除がすべて成功する。
- AC-22 (FR-1): 起動方式を指定せずに登録すると登録情報に起動方式が保存されず、指定して登録するとその値が保存される。
- AC-23 (FR-7): same-dir と worktree 以外の起動方式を指定すると、登録情報を作らずに失敗する。
- AC-24 (FR-6): 登録情報に effort がないとき、effort は medium で claude が起動される。
- AC-25 (FR-6): 登録情報に effort があるとき、その値で claude が起動される。
- AC-26 (FR-6): low・medium・high・xhigh・max 以外の effort では、claude を起動せずに失敗する。
